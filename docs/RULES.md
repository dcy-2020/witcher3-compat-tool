# v0.1 规则与边界

## 自动规则：function_local_set_map

- 原始名称：完全匹配的小写 `set` / `map`。
- 候选名称：`w3compatSet` / `w3compatMap`。
- 支持函数参数、`optional` / `out` 修饰参数、导入函数无函数体的参数、函数内 `var a, b : Type` 声明。
- 参数和局部变量的同函数引用一起处理；`.` 后的成员名称不处理。
- 支持 UTF-8（带/不带 BOM）、带 BOM 的 UTF-16 LE/BE。不能明确解码时停止，不猜测旧代码页。
- 不改注释、字符串、名称字面量、合法集合类型，不做文本全局替换。
- 保存字段、类字段、函数名、未知调用契约不会自动改名。

重复声明/遮蔽、目标名称碰撞、嵌套函数、同名集合类型混用、含糊的具名参数/标签、未解决的合并标记、不平衡括号、未知声明都会阻止该文件修复。分析器是有限语法识别器，不是完整编译器或类型解析器。

## 扫描范围

引擎脚本仅检查 `Mods/mod*/content/scripts` 和自定义 DLC 的相同目录。`~` 开头目录及官方 `bob`、`ep1`、`dlc1` 至 `dlc16` 不检查。目录内 `example/*.ws` 作为非加载示例提示，避免误报。链接目录/文件不跟随。提供 `mods.settings` 后还会排除 `Enabled=0`；优先级字段仅记录，不推断最终赢家。

重复脚本提示基于相同相对引擎路径与整文件 SHA-256，无法判定已合并文件是否保存了所有来源改动。工具不读取/更新 `MergeInventory.xml`。资源只检查松散文件头；包内资源、纹理缓存、XML菜单注册、ActionScript、字体以及运行效果均在覆盖范围之外。

SSS 提示是目录名启发式，不是完整天赋模组识别。核心脚本覆盖提示不意味着该文件有缺陷。只有一个本地旧模组集合的命名规则验证样本，不能估算整个模组生态的自动修复成功率。

## 文件安全模型

路径必须是规范的相对路径，不能含绝对路径、盘符、反斜杠、`..`、链接或 junction。应用不信任候选清单中的哈希声明，而是对当前源重新执行内置规则并比较完整字节。

备份覆盖本工具实际修改的脚本，保持只读文件原样并拒绝修改；无需复制整份游戏。每个事务先验证全部目标和备份，再原子替换单文件，逐次更新日志。失败时尽力还原已知状态；掉电/中断可使用同一事务回滚。外部修改状态保留，不强制覆盖。

清单和备份是本地信任输入，不是带签名的安全格式。保留事务目录，不运行其他人发来的清单；不要并行使用其他模组编辑器。工具锁只协调本工具的多个进程，不能锁住第三方软件。

## 扩展规则的要求

将新的自动规则加入前，必须定义触发版本、可靠识别条件、来源基线、保留的用户语义、停止条件及回滚范围。对共享/保存字段、天赋系统、UI以及二进制格式迁移，应优先实现扫描提示与精确版本适配器，并附真实运行验证；不要仅改格式版本号或以编译通过作为完成依据。
